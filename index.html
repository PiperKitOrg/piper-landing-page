Read-only

piper plan · migration planning

What happens when types don’t match?

Pick a target and Piper shows how your schema translates, and what could be lost, before anything runs.

Every type mapping has a class

Exact

Same meaning. Values unchanged.

Transformed

New type. Values preserved, including widenings such as unsigned integer → numeric.

Lossy

Information may change. Piper warns before execute. --strict-mode blocks it.

Example mappings

Strict mode

Use --strict to reject migration plans with known losses or skipped schema elements. Compatible substitutions remain allowed with warnings.

piper execute · writes target

See every table as it copies.

This is when the target changes: schema first, then each table with a row count. Large tables show a batch bar so a long run is measurable — not a blank wait.

Static source

Piper copies what it reads as it goes. Leave the source unchanged until you’re done.

Batch progress

Active tables show filled blocks and done/total batches.

Resume

If a long copy stops, piper resume continues from the last finished batch. Completed tables stay put.

piper validate · reads both sides

Piper checks the result without trusting itself.

After the write, Piper re-reads source and target for row counts, planned foreign keys, and recorded coercions — it does not trust execute’s report. Details in the docs.

skipped · left out of v1 on purpose

What Piper doesn’t do.

Limits are listed the same way as lossy types — so you’re never guessing.

No install step. Drop the binary anywhere and run it. For your own databases, see connections and first migration.

Checksums: downloads/SHA256SUMS. Playground: PiperKitOrg/piper-examples. Setup: Install.

  1. 1

    Clone your platform branch from piper-examples. The binary lands in bin/.

    git clone --recurse-submodules -b darwin-arm64 https://github.com/PiperKitOrg/piper-examples.git
  2. 2

    Start the sample databases with Docker Compose.

    docker compose up -d
  3. 3

    Inspect, then read the plan. Nothing writes to the target yet.

    bin/piper inspect && bin/piper plan --target postgres
  4. 4

    Execute when the warnings look right, then validate.

    bin/piper execute --yes && bin/piper validate
