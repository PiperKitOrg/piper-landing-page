What changes (and what doesn't)

Cross-dialect migration always rewrites something. Piper’s job is to make those rewrites visible before execute.

Supported, best-effort, unsupported

ClassMeaning
SupportedMigrated with a documented mapping (exact or transformed).
Best-effort / lossyMigrated with a warned degrade. --strict-mode blocks these.
UnsupportedSkipped with a warning, or rejected. Not silently dropped when Piper can detect it.

Types that often change shape

  • Integer widths may widen
  • UUID on MySQL is often emulated as VARCHAR(36)
  • PostgreSQL arrays toward MySQL may become JSON or delimited text
  • JSON / JSONB collapse in the intermediate model; PostgreSQL targets use JSONB
  • Float NaN/Inf toward MySQL become NULL and are counted in loss-report.json
  • Unbounded or oversized decimals toward Mongo may become float

CHECK constraints

A simple CHECK that fits Piper’s closed PostgreSQL↔MySQL grammar is preserved. Anything outside that grammar — functions, casts, LIKE, subqueries, and every CHECK aimed at MongoDB — is skipped with CHECK constraints will not be migrated. Strict mode blocks skips.

Relationships and foreign keys

  • SQL→SQL: foreign keys are transformed; actions are preserved when safe
  • Toward MongoDB: values only; not enforced
  • Mongo→SQL guesses: blocked until --confirm-relationship; orphans cause a skip, not a rewrite
  • FK cycles: default --cycle-mode strict fails the plan; use defer_constraints or manual_break

Objects Piper often skips

ObjectBehavior
RoutinesAlways skipped with a warning
TriggersOnly a narrow BEFORE UPDATE touch pattern; others skipped
ViewsSubset may translate SQL→SQL; not to Mongo
Roles / grantsNever migrated
RLS policiesDetected; not recreated
Expression / invisible indexesWarned; DDL skips
Generated columnsSnapshot values only; expression not re-emitted
Other Postgres schemasOnly the connected schema is migrated

Safety and limitations

  • Static source required — no live sync, no snapshot-isolation claim
  • New runs expect empty planned target tables
  • Completed batches stay on resume; Piper does not undo them
  • DDL is not crash-atomic
  • Failed migrations can leave partial schema and data; Piper does not clean up for you
  • Credentials are never written under .piper/
  • Offline plan uses assumed target capabilities; the live target may still reject DDL

For command-level detail, see CLI commands.
