MongoDB

MongoDB works as both source and target in Piper’s six cross-dialect directions. A few behaviors are Mongo-specific.

Inspect sampling

When MongoDB is the source, Piper samples collections to infer nested shape and field presence. The default sample size is 1000 documents.

command
piper inspect
piper inspect --sample-full

--sample-full reads every document. Use it when collections are small or you need fuller shape coverage. Large collections take longer.

Top-level keys and BSON types are still read from the whole collection; nested shape and presence ratios come from the sample.

Inferred relationships (Mongo → SQL)

Mongo sources do not declare foreign keys. Piper may guess from field names such as *_id or *Id.

Guesses stay blocked on the plan until you confirm:

command
piper plan --target postgres --confirm-relationship orders_customer_id

Confirming does not invent missing parents. If orphans exist at execute time, Piper skips that constraint, leaves rows unchanged, and prints why.

Foreign keys into MongoDB

When MongoDB is the target, relationship values can be copied, but they are not enforced as foreign keys in MongoDB.

Nested documents toward SQL

Nested documents and array elements are stored as JSON on the SQL side by default. Plan warnings call this out when it applies.

Other Mongo limits

  • MongoDB Date keeps only milliseconds — finer temporal values are cut
  • Decimal values may degrade to float when Decimal128 cannot hold them; plan warns; --strict-mode blocks
  • CHECK constraints are not migrated to MongoDB
  • Views are not migrated to MongoDB
  • Transactional checkpoints need a replica set or sharded cluster; otherwise Piper uses a local checkpoint
