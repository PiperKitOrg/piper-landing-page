Connecting databases

Piper dials only the two databases you name. Credentials stay in memory for the process — they are never written under .piper/.

URL schemes

EngineSchemesDefault port
PostgreSQLpostgres, postgresql5432
MySQLmysql3306
MongoDBmongodb, mongo27017
examples
postgres://user@127.0.0.1:5432/appdb?sslmode=disable
mysql://user@127.0.0.1:3306/appdb
mongodb://user@127.0.0.1:27017/appdb

How Piper finds a URL

For source and target, Piper checks in this order:

  1. --source-url / --target-url
  2. --source-url-file / --target-url-file (file mode must be 0600 or tighter)
  3. --source-url-stdin / --target-url-stdin
  4. PIPER_SOURCE_URL / PIPER_TARGET_URL
  5. source.url / target.url in .piper/config.toml (password-free only)

Passwords

Prefer PIPER_SOURCE_PASSWORD and PIPER_TARGET_PASSWORD, or let Piper prompt interactively. Avoid embedding passwords in URLs you save to disk.

Tip

Prefer a password that is not the word piper. Piper redacts known secrets from its own output; if the password equals the CLI name, hints like piper plan can show up as [REDACTED] plan.

Optional config.toml

example
# .piper/config.toml
[source]
url = "postgres://user@127.0.0.1:5432/appdb?sslmode=disable"

[target]
url = "mysql://user@127.0.0.1:3306/appdb"

[defaults]
batch_size = 1000
upsert_policy = "merge"
cycle_mode = "strict"
checkpoint_mode = "auto"

[inspect]
mongo_sample_size = 1000

Password keys are rejected. URLs with an embedded password are rejected.

Project root

Checked in order: --project-root, then PIPER_PROJECT_ROOT, then the current working directory. Piper does not walk up looking for a parent .piper/.

Which commands need connections

  • Source: inspect, execute, resume, validate, doctor, connect
  • Target: execute, resume, validate, doctor (when provided), connect (when provided)
  • Neither: plan (reads the saved inspect snapshot), status, runs, artifacts, explain, version

Quick connectivity check

command
./piper connect
