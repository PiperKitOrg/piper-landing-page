What Piper is

Piper is a single offline binary that moves schema and data between PostgreSQL, MySQL, and MongoDB — and shows you what will change before it writes anything.

The short version

You point Piper at a source database and a target database. It walks four steps:

workflow
piper inspect → piper plan → piper execute → piper validate

There is no account, no daemon, and no network call beyond the databases you name. Everything Piper writes stays in a .piper/ folder in your project.

Piper does not pretend a migration is lossless. Before it touches the target, piper plan prints every skip, every widened type, and every guessed relationship.

Who it is for

Use Piper when you need to move a working database to a different engine — for example PostgreSQL to MySQL, or MySQL to MongoDB — and you want a plan you can read before any write happens.

Six directions only

Piper only plans moves where the dialect changes. Same-dialect copies are out of scope on purpose.

Minimum versions: PostgreSQL 14, MySQL 8.0, MongoDB 7.0. MariaDB is not supported.

What Piper refuses

  • Same-dialect migration
  • Live sync / CDC / following ongoing writes
  • Roles, grants, and privileges
  • Multiple schemas in one run
  • Full routine and trigger translation
  • PostGIS as a support claim
