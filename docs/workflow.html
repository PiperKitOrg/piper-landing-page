Inspect, plan, and execute

These three commands are the core workflow. Validate comes after; resume re-enters execute.

Inspect

Before migrating anything, Piper needs to understand your database.

command
piper inspect

Piper connects to the source, reads tables (or samples Mongo collections), and stores a schema snapshot as ir.json under .piper/runs/<run-id>/.

  • Each inspect mints a new run id by default
  • MongoDB samples 1000 documents unless you pass --sample-full
  • Inspect does not write to the target

Plan

command
piper plan --target mysql

Plan maps the saved snapshot to the target dialect and lists warnings. It does not need a live target connection.

FlagWhat it does
--targetTarget dialect. Default postgres.
--strict-modeTurn degrading mappings into blockers (exit 4).
--cycle-modestrict (default), defer_constraints, or manual_break.
--confirm-relationshipConfirm a guessed Mongo→SQL relationship.
--detailsList every affected object from the saved plan without rebuilding it.
--forceRegenerate even when the plan fingerprint matches.

Warnings alone leave exit code 0. Blockers stop planning until you change flags or confirm relationships.

Execute

command
piper execute

Execute applies the plan to the target. Progress order:

  1. Schema (DDL)
  2. Data (batched row copy)
  3. Identity synchronization
  4. Triggers
  5. Foreign keys
  6. Deferred foreign keys (when cycle mode defers them)

Useful flags: --upsert merge|overwrite|fail (default merge), --checkpoint auto|local|target-transactional, --batch-size, --ddl-only, --no-ddl, --recovery, --yes.

Safety

Keep the source unchanged during execute. Piper does not synchronize ongoing changes or guarantee a consistent snapshot. A new run expects empty planned tables on the target.

PathPurpose
