Resume, status, and checking

Migrations get interrupted. Piper keeps progress locally so you can continue, inspect status, and validate independently.

Resume

command
piper resume

Resume continues a paused or failed run from the last completed batch. Finished tables stay on the target — they are not rolled back.

  • There is no piper pause command
  • If the process stops, the run may still look running; the next resume reclaims it under piper.lock
  • Cancellation via --timeout is recorded as paused
  • Resume is safe to retry under the default upsert merge
  • With --upsert fail, a crash after apply and before checkpoint can surface duplicates

Source must stay still

Resume assumes source data has not changed since the original run. Piper does not follow ongoing writes.

Incomplete run vs a new inspect

Each piper inspect creates a new run id. If an incomplete run already exists for the same endpoints and plan fingerprint, plan warns and execute refuses a new copy unless you pass:

  • --recovery resume or --resume-run <id> — continue the original run
  • --recovery fresh — empty target, new run
  • --recovery continue / --allow-existing-target — new run with no inherited checkpoints

--yes does not pick a recovery mode for you.

Status and runs

command
piper status
piper runs

status shows the current state, progress, and latest validation for a run. runs lists runs stored in this project’s .piper directory.

Validate

command
piper validate

Validate independently assesses the outcome. It does not treat execute success as proof.

Default checks:

  • Row-count parity for migrated entities
  • Orphans for foreign keys the plan intended to create
  • Recorded non-finite float coercions from loss-report.json
  • Warnings for JSON-as-text and precision-loss strategies

Validate does not repair rows, recreate skipped objects, or prove every semantic difference. Exit 5 means a check failed.

Doctor and explain

command
piper doctor
piper explain

doctor is a preflight report (connectivity, versions, optional ledger integrity). A green doctor is not proof the target matches — use validate.

explain shows the latest recorded failure for a run and suggests what to try next.
