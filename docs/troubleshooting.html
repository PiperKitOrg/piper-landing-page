Troubleshooting

Start with piper explain and the plan warnings. They are usually more specific than a generic error line.

First moves

  1. piper explain — recorded failure and a next step
  2. piper doctor — connections and versions
  3. Re-read the plan warnings — they are the contract for that run

Exit codes

CodeMeaning
0Success
1Generic error
2Usage / config
3Connection / auth
4Plan blocked (cycle, unsupported mapping, capability, planning)
5Validation failed
6Migration / duplicate key failure
7Cancelled
8Run conflict / not found / ledger
9Corrupt artifact / unsafe path

Common situations

Same dialect rejected

Source and target must differ. Pass the correct --target. Default target is postgres.

Version too old

Piper stops below PostgreSQL 14, MySQL 8.0, or MongoDB 7.0. MariaDB is not supported. Newer than tested versions warn and continue.

Target already has data

Empty the planned tables, or pass --recovery continue / --allow-existing-target knowing the new run starts from cursor zero with no inherited checkpoints.

Incomplete migration detected

Prefer piper resume or piper execute --recovery resume / --resume-run <id>. Do not invent progress by starting a fresh inspect unless you mean to.

piper.lock held

Another execute or resume still holds the lock (piper.lock held by pid N). Wait for it to finish, or investigate that process.

Missing run / plan / IR

Run inspect then plan before execute. Piper does not invent a schema.

Plan blocked on relationships

Confirm inferred Mongo relationships with --confirm-relationship, or adjust cycle mode for FK cycles.

Validation failed (exit 5)

Read the validation report. Validate does not repair data — fix the cause, then re-run validate.

Not verified on this site

Installers that are not listed in the homepage download table (for example third-party package managers) are outside what this documentation verifies. Use the binaries shipped here, the platform branches of piper-examples, plus SHA256SUMS.
